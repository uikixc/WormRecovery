# WormRecovery 1.7.2

- 扫描与处理分别生成独立操作编号，保留同一会话编号、操作类型、开始结束时间和完成、停止或失败状态。
- 每个操作结束立即复制报告和日志到 operations/操作编号/，先进入上传队列，再允许后续操作覆盖当前汇总报告。
- 只扫描即可上传，不需要先处理。处理与复扫完成后另存、另传，保留处理前的证据。
- 命令行扫描的进程、注册表和持久化检查固定使用只读模式；修复仅由明确的处理操作触发。
- 上传继续采用 HTTP + gzip。接收端本地汇总增加扫描与处理份数；原文件、隔离样本不随日志上传。

验证：206 项回归测试通过，包含扫描与处理快照分离、异常及停止日志、独立操作编号、上传包携带操作类型、只扫描不调用修复接口，以及上传期间新增日志继续发送、暂停提交后不重复创建线程。

当前研究流程：先扫描并上传，分析后再由使用者明确执行处理。未收到处理指令时保留感染文件和研究样本；日志上传不会执行远程清理。
