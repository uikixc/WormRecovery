# WormRecovery 1.8.11

此前确认恶意载荷的处理不会覆盖仍待核的打包图片与DLL，签名宿主也未显示在关联组中。因此只删确认项并不表示整组已处置。

- 新增“关联部署残留”：同目录精确匹配的已知打包DLL及尾随编码图片一起显示；已知宿主只在其实际导入的XPSPLOG.dll内容匹配时加入。宿主改名仍可识别，单独合法宿主不报。
- 这些是已观察配套关系，不声称已证明全部独立恶意行为或运行链。确认恶意载荷仍按原有恶意代码证据判定。
- 点击处理后另列出每个关联成员：选择“是”明确同意删除这些文件（含签名宿主），选择“否”只处理确认感染。普通待核项不因此获得删除权限。
- 关联组先完整复核内容、保护范围与链接状态，再逐文件复核删除。改变或缺失成员会阻止处理；同会话已验证删除记录可用于剩余成员重试。日志不能跨会话自动授权。
- 不递归删除目录、无关文件，不创建感染文件备份。未批准或失败的组仍显示为未解除风险，复扫不能宣称清理完成。关联组不再送入耗时的补充引擎。
- 命令行需显式使用 `--clean --include-observed-deployments` 才包含关联组，单独 `--clean` 保留配套待核项。

研究目录通过本机 device-protection.json 的 excluded_paths 配置保护，设备路径不写入公开源码。保持研究样本完整需要正确配置这些路径；公开工具不能自行识别所有研究目录。

本版本不执行样本。测试仅用无害fixture；实际感染目录验证仅做只读扫描。真实处理效果、其他电脑更新及大规模合法库边界仍需用户验证。

本版验证：493项无害回归通过；实际打包成品只读扫描16文件，原目录识别2组6成员，加上改名组共4组11成员。单独合法签名宿主及无害同名边界共5文件未报。文件阶段2.625秒，总流程21.812秒，异常0；未调用补充引擎，所有原件和测试副本哈希不变。这不代表百万文件性能或其他电脑实测。
