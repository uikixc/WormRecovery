# 日志服务的更新分发

日志接收服务可以同时提供已签名的正式版本，客户端通过内网或公网线路直接读取，无需依赖系统代理。日志接收与更新下载使用独立的并发限制，下载不会占满所有诊断接收位置。

更新目录默认是日志存储目录同级的 `updates`。也可以在服务端本地配置中设置 `updates_directory`。公开接口只有以下两个精确路径，不提供文件目录列表或远程发布功能：

- `GET /updates/stable/update-manifest.json`
- `GET /updates/releases/v<版本号>/WormRecovery.exe`

接口支持 `HEAD` 以及单段字节范围下载。客户端必须验证固定公钥的 Ed25519 发布签名及完整文件大小、SHA-256；HTTP 响应成功不代表文件可信。服务端也在首次读取或文件状态变化时核对附件哈希，缓存校验结果用于减少重复读取，客户端的完整校验始终保留。

先使用 `prepare_release.py` 在本地生成正式签名附件，再运行：

```powershell
python publish_collector_update.py --source <已签名的版本目录> --destination <服务端更新目录>
```

发布工具先验证签名与附件，再复制到新的版本目录并重新校验，最后原子替换稳定版清单。同一个版本的内容不可替换，也拒绝将稳定版回退到较低版本。旧版本继续保留，已经开始的下载可以完成。如果发布中断留下 `.publish.lock`，先确认没有其他发布进程，再处理该本地锁文件。

更新目录仅放正式发布附件。样本、日志、接收凭据、签名私钥及设备配置不属于更新包。服务端更新不修改已有诊断数据和接收配置。
