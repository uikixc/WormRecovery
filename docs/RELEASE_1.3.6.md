# 1.3.6 离线分析增强：本机验证构建

日期：2026-11-05。

## 已实现

- 未知 OOXML 宏项目由独立进程进行 VBA 源码、MacroRaptor 标记和 pcodedmp 编译指令特征提取，结果写入报告。内容相同的项目在进程内复用成功结果。
- 源码家族特征命中且没有其他业务宏时，还要求编译代码中的家族特征同时匹配，才沿用现有自动恢复流程；仅凭可疑标记不自动移除宏。
- 在检查 VBA 前检查 XLM 宏表、自动运行名称、DDE、嵌入对象、ActiveX 及非普通超链接的外部关系；即使没有 VBA 项目也记录这些内容。额外活动内容不能被组件哈希说明覆盖，也不能通过仅删除 VBA 自动认作恢复完成。
- 计划任务和服务取消固定家族名称预筛选，枚举目标后核对内容；WMI 增加脚本消费者、过滤器和绑定的清单。确认恶意消费者的删除前再次核验身份和内容，移除关联绑定，保留可能共享的过滤器。
- 注册表增加 Windows、Winlogon 和 Command Processor 入口检查。共享启动值命中时报告需要进一步处理，不整体删除 Shell/Userinit 等值。

## 本机验证

- 99 项无害回归测试通过，包含新增的活动内容、源码与编译证据、解析超时、独立进程和持久化枚举测试。
- 实际只读枚举返回 100 个任务动作、267 个服务和 1 组 WMI 绑定；没有确认的家族目标。这个结果只描述该次本机枚举，不是全系统无毒证明。
- 打包后的分析进程成功读取现有 Office 组件的 31 个模块及编译指令，不启动 Office。
- 打包 CLI 扫描 3 个无害夹具：普通文档、含 XLM 结构的文档、包含现有合法组件宏的文档；2 项保留为未确认，0 个解析错误，退出代码 3，扫描前后文件哈希一致。

## 使用

将 WormRecovery.exe、WormRecovery-CLI.exe、WormRecovery-Analysis.exe 保留在同一目录。启动图形程序后，先执行扫描，再按结果处理已确认感染。宏分析运行不依赖 Codex 或远程服务；构建时已包含所需 Python 库。
