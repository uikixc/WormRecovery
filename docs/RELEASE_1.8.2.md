# WormRecovery 1.8.2

本版本将已完成的 REA 逆向结果转化为可在其他计算机离线运行的内容检测规则及静态解析器。检测过程不启动被检查程序、不执行宏或脚本，也不联系样本内的远程地址。

## 内容判定

- Synaptics 包裹感染继续使用感染代码节的完整 SHA-256，并依据资源结构区分可恢复程序与独立载荷；不再要求特定入口地址、节名或恰好八个节。Office 仍由宏源码、已知宏内容及可用编译指令交叉判定。
- Perfr-RandomX 矿工要求同时匹配矿池配置代码、配置更新代码和挖矿协议内容。普通 RandomX、Monero、Stratum 字符串或 UPX 壳不足以判定恶意。
- 匹配已观察的改造压缩层时，解析入口的相对地址并静态执行字节层面的 XOR/NRV2E 解码，再检查内部矿工代码。这里没有执行目标机器指令，也没有把解码数据宣称为可运行的完整原程序。
- 加密更新项目必须通过 ZIP CRC 校验，并同时包含本家族机器码组合及内存装载脚本组合；不按外层 DAT 名称判断。
- PNG 载体按已恢复算法静态解密，核对内部 PE 结构及控制 DLL 的多段代码。名称生成算法、部署代码和注册表控制代码共同构成规则；普通图片不会仅凭后缀被检出。
- 有效签名的更新运行时自身不属于感染证据。只有运行时实际读取的同基名 DAT、PNG 配套位置同时出现已解密并内容确认的恶意项目及控制载荷，才记录其恶意部署关系。配套路径只用于确认加载关系，不是恶意证据；同目录不相关的恶意文件不足以判定正常运行时。运行时身份使用内容哈希绑定，文件名和签名发布者不授权处理。
- 尚未完成逆向的受保护样本仍明确保留为待核查，不能为了减少计数而判为安全或直接认定恶意。
- 程序中的机器码特征必须属于外层 PE 的可执行节。位于嵌入映像、资源或尾部附加数据中的命中保留为复核线索，不授权整份隔离正常宿主。原版 AutoIt 解释器需要实际配套恶意脚本的完整内容证据；缓存样式名称不能单独授权处理。

## 扫描与处理

此前未知扩展名会在调度前被过滤。现在所有选中文件都进入受控的文件头检查，PE、已知 PNG 载体和非 Office 加密项目按内容进入对应解析流程。读取仍按物理磁盘控制并发；静态解包仅用于匹配已知压缩代码的候选，不逐个启动大型外部分析器。

单文件家族分析上限为 16 MiB，载体分析上限为 4 MiB，解包输出上限为 16 MiB、单次解包预算为 3 秒。超过上限、解码不完整、未知加密和其他壳均不构成安全认证。报告包含实际调用计数、解码方法、内部内容哈希、命中规则与关联文件证据。

用户选择处理后，新确认的独立恶意载荷必须重新核对内容并保留隔离副本。关联运行时必须重新验证双方内容；如果关联文件已在本次处理中隔离，则核对隔离事件和备份的完整内容。文件在扫描后变化时停止处理。被感染的正常程序与 Office 文件继续使用原位恢复流程，不以整份删除代替业务内容恢复。

Office 恢复按 XML 结构移除确认的宏成员、关系及类型声明，兼容单引号和命名空间前缀，并校验剩余关系目标、重复标识及工作表原始字节。无法验证的输出不提交原位替换。任务定义、服务映像和进程创建时间在操作前重新核对；先处理已确认持久化再核对活动进程，保留处理前证据用于复验已经缺失载荷的启动项。此流程仍不能宣称原子阻止任意恶意程序再生。

普通大 PNG 和 ZIP 先做受限内容探针，不因超出家族解码限额一律记为可疑载体。匹配加密 PE 前缀或加密项目结构后无法完成解析，仍明确保留待核查；大型程序、脚本、读取失败和其他未完成项目继续阻止“清理完成”。

构建默认输出到 `release/WormRecovery-1.8.2/`，可通过 `build.ps1 -OutputDirectory <目录>` 指定新的版本目录。不会把新发布程序写回旧版 `dist` 文件夹。

真实样本、原始反编译报告、用户文件和诊断数据仅保存在私有验证目录，不属于源码或发布附件。规则仅覆盖已观察家族；并未将 Ghidra、未知恶意软件的完整自动逆向或离线注册表处理能力宣称为已接入。

## 单文件启动与更新

交付仍只有 WormRecovery.exe。启动器把完整运行时按嵌入清单的 SHA-256 分版缓存在 ProgramData/WormRecoveryRuntime；首次启动展开，后续复用。缓存仅管理员与 SYSTEM 可访问，启动前逐文件验证完整哈希、权限及重解析点，运行期间保持文件只读锁。缓存验证失败时拒绝执行；不会以长度或修改时间代替哈希。独立宏分析组件改用目录运行时，减少每次进程启动的重复展开。GUI 启动立即显示准备/验证进度，首次展开时可取消且清除该次暂存目录；命令行启动不弹出进度窗口。启动器使用 .NET Framework 4.6.2 或更新版本，并显式处理扩展路径，无需启用系统 LongPathsEnabled。

更新安装识别真实父进程链中的外层程序路径，等待启动器退出后替换用户复制的外层 EXE，并保留旧版备份。无需令牌时先直连自用更新服务，失败后回退 GitHub；所有请求禁用系统及环境代理。自用 HTTP 服务限定来源与路径、拒绝重定向且不发送凭据，清单必须通过固定公钥 Ed25519 验证，下载必须通过完整 SHA-256 验证。

启动耗时需分别验证首次展开与后续启动，不能把仅有缓存的结果当作新电脑首次启动耗时。开发机已确认直连 GitHub 可用；其他电脑报告的网络失败尚未在本机复现。离线功能不依赖更新服务。

更新服务器扩展、单版本不可变发布及单段字节范围下载见 [更新分发说明](COLLECTOR_UPDATES.md)。旧客户端仍使用其原有 GitHub 检查逻辑；首次换用本版后才具备内置直连更新源。
