# WormRecovery 1.8.8

修复 1.8.7 及以前对每个待处理文件都完整复制后再校验备份的问题。旧实现对大文件没有大小分支，20 GiB 文件也会进入复制流程。

- 取消此完整复制：程序原位恢复使用 Windows ReplaceFileW，将原文件移至同卷专用目录并提交已验证的恢复文件；隔离和扩展名变化的文档恢复使用同卷重命名保留原件。日志明确记录 same_volume_move 与 copied_bytes=0。
- 原件保存在其所在卷的 WormRecoveryQuarantine/会话目录；目录及每个原件均设置管理员和 SYSTEM 专用权限并核对，原文件权限随日志保存，恢复出的文件还原原权限。已有目录须验证所有者、ACL 和路径无重解析点，信任失败或原件含多个硬链接则拒绝处理。原件仍占原有空间，但不再因备份多复制一份。
- 同卷移动或替换失败时不回退跨盘复制；尚未提交时尝试恢复原路径，已有新占位文件则保留双方并报错。移动前先写原件位置日志，保留中断恢复依据。
- 扫描排除已验证的专用原件目录，后续关联判定仍可读取本轮已移动的原件内容，避免重新当作活动感染或丢失已处理关联证据。
- 保留处理前完整哈希/内容复核；提取和生成恢复文件仍需要读写实际内容，不能承诺大文件瞬间修复。此次不删除用户既有备份或研究样本。
- 文档目标扩展名变化时，若同名目标在处理期间出现，保留双方，回移原件，不覆盖新目标。

验证仅使用无害文件和合成故障；未执行病毒样本、未实际清理感染电脑。目标电脑实际处理耗时待更新后复测。

## 本轮验证

- 460 项无害回归通过（51.132 秒）；覆盖同卷移动、实际 Windows 文件替换、原件私有权限、恢复文件权限还原、故障回滚、多硬链接拒绝，以及两种扩展名路径的 Office 恢复和目标冲突保护。存在既有 Tk after 退出输出及可选 pywin32 提示，不称零警告。
- 20 GiB 无害稀疏文件验证移动前后文件身份和逻辑大小不变、未调用完整复制。该项用模拟哈希，未测真实 20 GiB 全量读取或实际感染文件恢复速度。
- 实际 1.8.8 成品只读扫描 4 个文件：两种改名/扩展名 TSCO 均 identified/review_binary，无害普通 PE 和只读节别名无误报，检查异常 0，补充引擎未调用，原样本和副本哈希不变。共 16.531 秒，文件阶段 0.297 秒；不是百万文件性能或真实恢复测试。
