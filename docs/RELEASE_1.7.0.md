# WormRecovery 1.7.0

- 新增诊断反馈：采集扫描日志、待核项及判定依据、解析与引擎错误、恢复结果、扫描性能和更新故障。导入设备配置后自动后台提交；断网保留加密队列。
- 新增独立 TCP 10888 HTTPS 接收服务，内网优先、外网备用，提供设备授权、证书指纹校验、端到端加密、存储配额、90 天保留期限和本地汇总命令。
- 客户端仍为一个可执行文件。服务端部署说明见 DIAGNOSTIC_COLLECTION.md，提供 Windows 开机任务安装脚本和 Linux systemd 部署脚本。采集不包含文档原件、正文或隔离样本。
- 包含 1.6.0 的离线判定修复：跨盘符核对已知 Office 组件；核验本地图片及外部工作簿关系；宏源码及编译指令行为组合判定。没有足够依据的宏和解析失败项继续明确显示。
- 包含 1.6.0 的更新修复：GitHub API 失败时尝试公共发行附件中的 Ed25519 签名清单；不能通过签名校验的内容不用于安装。网络失败保留具体诊断原因。
- 修复成品程序的 HTTPS 初始化失败：构建过程保留当前 Python 运行时要求的证书资源，避免更新检查与诊断上传在打包后因缺少文件而失效。

资料收集帮助后续完善规则，并不意味着自动训练或可以保证所有未知待核项都能判定、修复。服务端必须部署且客户端导入有效配置后，才能接收实际报告。

验证结果：197 项回归测试通过；独立单文件客户端与成品接收服务的本机 HTTPS 收件、脱敏、授权存储、接收凭据、原报告不变、暂停和汇总检查通过。成品命令行更新检查已成功读取 GitHub 发行信息。Linux 部署脚本尚需在目标 Linux 系统验收。
