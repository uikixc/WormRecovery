# WormRecovery 1.4.0 离线多引擎集成

## 已接入

- YARA-X 1.22.1：复用已编译内容组合规则和工作线程扫描器；单独文件名不触发家族判定。
- ClamAV 1.5.4：批量检查未解决候选的私有副本；main/daily/bytecode 病毒库内置。daily.cvd 版本 28173，构建日期 2026-11-03；本机日期为 2026-11-05。离线库不会自动获得未来新增情报。
- AutoIt-Ripper 1.2.0：静态提取支持格式中的脚本并计算规则和哈希；不支持的 A3X 格式明确报告。
- XLMMacroDeobfuscator 0.2.7：提取 Excel 4.0 宏单元格并作有界模拟，不调用 Excel、不运行提取命令；缺少入口、未解析指令或超时保留未完成状态。
- capa 10.0.0：自动识别候选 PE 的程序能力，25 秒超时；正常程序也具有文件操作等能力，能力列表不等于恶意结论。
- REA 6.8.0 与 Node 26.13.0：自动解析 PE 导入、延迟导入、导入哈希和覆盖信息，记录真实 Evidence ID。没有捆绑 Ghidra/JDK；导入信息不是完整源码恢复。
- 原有 oletools 0.60.2、MacroRaptor 和 pcodedmp 1.2.6 的 VBA 源码、编译指令检查保留。

## 执行与恢复

用户只需复制 WormRecovery.exe，目标电脑无需 Codex、Python、Node 或联网安装。内部程序与数据库由主程序自动解包管理，因此体积、启动时间和临时空间占用增加。分析工作区和内嵌组件不进入自身的全盘扫描范围。

筛选阶段保留物理磁盘感知的有界线程；深度引擎只检查未解决候选，ClamAV 每批只加载一次病毒库。分析进程使用 Windows 作业对象约束生命周期及总内存，取消或超时结束任务及子进程。副本准备前后校验文件身份，原件不交给外部引擎修改。

引擎检出、规则命中、无已知匹配、格式不支持及执行失败分别记录。未知业务宏不会因为多数引擎无匹配就被认证安全；通用杀毒检出也不直接授权删除整份文档。自动恢复继续依照已验证的家族结构、同路径历史原件和内容一致性规则执行。

## 验证

- 118 项无害回归测试通过，包含规则正负例、ClamAV 结果解析、组件篡改拒绝、XLM 实际提取和模拟、未知原件保留、分析超时、子进程回收和界面分类。
- 真实引擎使用无害 HALT 宏表、普通文本和 Windows where.exe 的私有副本。ClamAV、XLM、capa、REA 均实际返回结果，三个输入文件前后 SHA-256 一致。此验证不代表未知家族的通用检出率。
- 另一台电脑的 52 项报告尚未取得，没有对这些项目作具体判定。

单文件独立运行验收：只复制一个 EXE 到空目录，将 PATH 限定为 Windows 目录，清除 Python/Node/引擎路径环境配置；对无害 XLM、未知 AutoIt 和附加静态组合字符串的 Windows 工具副本执行只读扫描。ClamAV、XLM、capa、REA 实际返回结果；AutoIt 不支持格式明确报告；所有输入内容一致。由于测试特意包含不支持的格式，扫描返回未完成状态是预期结果。该测试在本机执行，尚未替代另一台断网电脑或虚拟机的验收。
