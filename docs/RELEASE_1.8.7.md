# WormRecovery 1.8.7

本版减少启动和处理过程中的重复磁盘读取；备份仍用于保留处理前原件和回滚依据。

- 单 EXE 内的核心运行文件与可选引擎分开缓存。启动只展开、完整校验并锁定核心程序、命令行与必需 Office 解析组件；ClamAV、REA、capa 等在用户启动待核项补充分析时才准备。全部内容仍随 EXE 离线提供，不需要联网下载组件。
- 可选组件由当前外层启动器通过受权限保护的随机通道提供，客户端核对管道服务进程身份；组件启用前核对完整清单、SHA-256、权限与重解析点，并保持禁止写入/删除句柄直到应用退出。缓存被篡改仍拒绝使用。
- 修复过程保留每项前的进程枚举。只有同一映像已完成检查、持有禁止写入/替换的只读句柄、文件身份未改变时，才复用本轮内容检查结果。无法取得稳定句柄、新映像、已确认恶意映像、AutoIt 解释器、依赖关联证据的运行时均继续重新检查。处理结束或出错释放本轮句柄。
- 备份和原文件提交前的完整校验保留。日志分别记录每次备份、进程检查及处理阶段耗时，进程记录包含实际重查/复用次数。复扫仍报告自己的文件检查耗时，待核项不会自动启动补充引擎。

定位依据：最新用户处理报告总耗时约 423 秒，其中文件复扫约 225 秒。41 次备份共约 628 MiB；原日志没有备份独立耗时，不能把其余时间都归因于备份。多次小文件恢复间隔约 3–4 秒，旧实现每项重新读取运行中程序映像。上述为历史日志与源码定位依据，不是新版实机加速承诺。

已验证：446 项全量回归通过（20.627 秒；有既有 Tk 定时回调退出输出）。无害启动器测试覆盖正常启动不展开可选组件、显式请求才展开、运行期间拒绝写入，以及篡改后恢复时间戳仍被拒绝；进程检查测试覆盖稳定读句柄复用、无法锁定时重新检查和异常释放句柄。

实际成品的核心清单为 2,424 文件、220,283,922 字节；8,397 文件、578,078,958 字节的可选组件在常规扫描时不准备。4 文件只读成品检查无检查异常，两个改名或更换扩展名的 TSCO 内容仍为 identified/review_binary；无害 PE 和只读节别名边界未误报，原样本与副本哈希不变，补充引擎均未调用。另一次仅含 1 个无害合成 PE 的显式补充分析成功准备可选组件，ClamAV 返回 no_match、REA 静态导入检查完成，capa 保持 not_requested；无检查异常。这些是有限验证，不代表百万文件或真实恢复性能。

验证仅使用无害合成文件与只读诊断。真实样本保持原样，不执行样本或真实清理。目标电脑全盘扫描、实际恢复和启动耗时仍需更新后复测；保留待核项和检查受限状态，不能据此声称整机安全。
