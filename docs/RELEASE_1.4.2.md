# WormRecovery 1.4.2 扫描性能与读取异常说明

## 性能

最新用户报告中，1.4.1 用 62.531 秒检查 214,939 个文件，4 个扫描线程。此前 1.3.7 同机报告为 206,827 个文件、19.75 秒。目录和文件数量有变化，这些历史记录不能当作严格对照，但新增内容规则造成的读取开销确实存在。

只读采样发现，约 42,273 个程序文件进入 YARA-X 规则检查，累计目标长度约 15.2 GB。1.4.2 对原本已限制为 16 MiB 内的程序候选按实际长度读取一次，供包装检查、适用的哈希检查及原有 YARA-X 规则共同使用，检查时文件长度变化则明确失败。大文件的既有处理方式保留；不是只扫文件头，不跳过正常程序目录，也没有扩大白名单。

移除文件规则扫描前重复的空数据扫描，非阻塞队列轮询直接收集已完成任务，避免反复创建等待器。按物理磁盘限流的并发预算保持不变。报告新增文件扫描和候选深度复核的分段耗时。

候选方案曾使用统一最大读取长度，实测更慢，已撤回；最终按实际文件大小读取的源码全盘验证约 215,878 个文件、39.110 秒。该值来自本机一次运行，会受缓存、后台负载、磁盘及候选文件影响，不保证其他电脑固定加速倍数。最终 EXE 实测另保存在本地验证报告。

最终 EXE 本机全盘只读验证：225,155 个文件、52,730 个目录，扫描阶段 47.297 秒；含单文件解包启动、系统检查和退出，共 61.547 秒。相邻 1.4.1 成品验证为 225,078 个文件、62.313 秒扫描、73.8 秒总耗时。两轮并非控制全部变量的实验，主要用于确认改动没有使当前成品变慢；完整内容规则和检查范围不变。新版报告确认感染 0、待核查 0、信息项 8，读取限制 2。

## 两处异常

- C:/pagefile.sys：EnumPageFilesW 枚举到的活动分页文件；系统拒绝普通在线读取。
- C:/swapfile.sys：位于系统卷根目录的交换文件路径，同卷存在已登记的活动分页文件；该文件的内容未验证。

界面“检查异常”筛选现在显示路径、读取限制原因、原始错误与后续说明。两项仍留在错误及覆盖限制中，内容检查状态为 false；没有因为路径常见而认证安全，也没有通过关闭虚拟内存、终止系统进程或忽略读取错误来制造零异常。

如果错误发生在其他同名目录、不同卷、非权限错误，或系统接口未能确认分页文件身份，仍按普通检查异常处理。需要读取活动内存后备内容时，必须另行采用可信离线检查流程，本版本没有自动执行该流程。

## 验证

132 项无害回归测试通过，涵盖规则正负例、真实 VBA 通信、程序单次读取、文件变化拒绝、队列调度、分页文件精确路径分类和界面异常显示。外部离线引擎与单 EXE 交付方式保持，研究设备和本机排除配置不变。
