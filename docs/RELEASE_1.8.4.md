# WormRecovery 1.8.4

本版包含更新连接修复、后台检查关闭修复，以及 TSCO 当前已知内容的离线组合识别。版本为 1.8.4，内容规则版本为 2026.11.06.3。

## 更新连接与启动

- 修复保存旧设备令牌时绕过自用更新服务的问题。先尝试无凭据的已签名内外网服务；服务成功时不读取本机凭据，令牌仅用于 GitHub 回退。
- 自用服务、GitHub API、公共备用清单分别设有 4、12、8 秒墙钟总时限。已知私有仓库的 API 挂起或签名校验失败不会转向公共镜像。
- 后台版本检查不再阻止关闭窗口；下载仍遵循取消流程。关闭时取消日志连接的延迟回调，服务 HTTP 错误保留来源与状态码。
- 自动更新在主界面建立后约 3.5 秒后台开始。首屏前的离线组件完整 SHA-256、权限、重解析点检查与句柄保护独立于联网。一次本机 1.8.3 现有缓存校验测量为约 7.70 秒，涉及 10,820 个文件、796,759,457 字节；不代表其他电脑或首次展开的总耗时。本版未削弱或更改启动器完整校验。

## TSCO 离线内容识别

- 组合核对当前根 PE 活动入口锚点、固定描述表与参数、四条有界完整 EOS 压缩流、消费者范围内减一变换、四个完整内部 DLL 身份。根 PE 不相关时间戳改变仍可识别，文件名和扩展名不参与判定。
- 四个已知完整内部 DLL 可独立识别。仅覆盖当前冻结内容，不声称覆盖未知变体或整个家族。
- 身份为 `identified`，扫描结果为 `review_binary` / `known_payload_content`，显示“已知载荷内容，归属待核”。该身份不直接确认挖矿或文档蠕虫，也不授予清理权限。独立已确认恶意代码证据保留判定优先级。
- 父 PE 内嵌内容单独报告偏移、长度与身份，父文件不继承载荷的恶意身份。没有声明支持任意 PDF、ZIP 内部载荷解析；将 PE 改名为 PDF 仍按真实文件头识别。
- 候选数量、解压输出、流结束和输入消费均有边界；篡改、组合不全、超过限额均保留未完成状态。大型 PE 只读映射支持内容身份，源文件改变会撤销旧身份。
- 通用 UPX、AutoIt、LZMA、ChaCha、API 或模块名不能单独确认 TSCO。尚未用大规模合法软件库评估误报率。

## 验证与限制

- 1.8.4 源码全量回归 426 项通过，约 18.02 秒，包括更新 35 项、界面 23 项、TSCO 合成边界 17 项及既有大型 PE 与离线引擎回归。
- 已保留真实内容只读验证 18 项通过：原内容、改名、时间戳改变、错误入口、压缩篡改、无害父 PE、四个内部 DLL 及其变化、通用字符串阴性、原件哈希保持。只读静态解析，未执行样本。
- 单文件成品已构建，帮助和版本检查均可运行，GUI 与 CLI 的打包模块均包含 TSCO 分析与特征。
- 实际运行该单文件成品，以只扫描模式检查两个改名副本和一个无害通用字符串 PE：两个副本均保留四流、四内部 DLL 的 `identified` / `review_binary` 结果，无害文件未产生发现，原件哈希保持。ClamAV 批量检查与 REA 静态导入分析完成，但两个副本的 capa 复核均达到原有 25 秒限额，因此总扫描明确返回“未完成”及退出码 1；不把内容识别通过写成全部引擎通过。
- 另一台电脑的实际连接故障和首次展开总耗时仍需复测；本机连接成功不等于所有电脑故障已解决。
- 本轮没有实际清理、修复、隔离、终止进程或移除持久化，没有启动或唤醒子智能体。
